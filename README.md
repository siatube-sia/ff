# Browser Audio + Video Merger

動画ファイルと音声ファイルをブラウザ内で結合し、MP4として保存するシンプルなWebアプリです。

- サーバーへのメディアアップロードなし
- ffmpeg.wasm によるブラウザ内処理
- 動画の元音声を、選択した音声へ置換
- 音声が短い場合は動画尺までループ可能
- 高速な映像ストリームコピー + 失敗時のH.264自動フォールバック
- 音声のみ・映像のみの時間指定切り出し、保存後に次の範囲へ移動
- 入力はWORKERFSで部分読み込みし、処理ごとにワーカーを終了

## 切り出してから結合

1. 「操作」で「音声のみ切り出す」または「映像のみ切り出す」を選び、ファイルを選択します。
2. 開始・終了を指定します。10分のファイルなら、例えば `0:00`〜`5:00`。秒数や `時:分:秒` も使えます。
3. 「指定範囲を切り出す」を押し、音声はM4A、映像は音声なしのMP4で保存します。指定位置から切るため再エンコードします（映像はH.264）。精度はフレーム・音声サンプル単位です。
4. 保存完了を自分で確認してチェックし、「保存したので次の範囲へ」を押します。前の出力を解放し、次の範囲（例：`5:00`〜`10:00`）を設定します。最後の範囲は元ファイルの終端までに短縮します。別の範囲を手入力することもできます。
5. 音声と映像の同じ区間を保存したら「保存したファイルを結合する」から、その2ファイルを選び直して結合します。これは映像と音声の組み合わせであり、複数の動画を時系列につなぐ機能ではありません。

入力は[WORKERFS](https://emscripten.org/docs/api_reference/Filesystem-API.html#filesystem-api-workerfs)に元のFileを読み取り専用でマウントし、ファイル全体のArrayBuffer化を避けます。切り出しは入力側でシークし、指定時間だけ出力します。ただし形式情報・インデックス・直前のキーフレーム等も読み、形式によってはシーク時に広い範囲を走査するため、指定区間以外を一切読まない保証はありません。出力は1本のみメモリに保持し、次へ進む際にプレビューとBlob URLを解放します。毎回FFmpegワーカーを終了して作業領域を解放しますが、ブラウザのメモリ回収時期は保証できません。WORKERFS未対応時は全体コピーに戻さずエラーにします。

## 起動

Node.js が入っている環境で:

```bash
npm install
npm run dev
```

表示された localhost のURLをブラウザで開いてください。

## 本番ビルド

```bash
npm run build
npm run preview
```

## 注意

初回処理時に FFmpeg core（約30MB）をCDNから読み込みます。その後の動画・音声処理自体はブラウザ内で行われます。
大きな動画は端末メモリを多く使用します。

## メモリ使用量の目安

画面には、入力ファイルの合計サイズ × 4 + 256MB（H.264変換オンでは × 6 + 512MB）を目安として表示します。入力・出力のメモリ内コピーと処理領域を考慮した未実測の概算で、上限保証ではありません。例えば合計100MBなら約656MB、500MBなら約2.26GBです。解像度、コーデック、動画尺、音声ループ、自動H.264変換、繰り返し処理などによって実際の使用量は変わります。

端末メモリを取得できるブラウザでは、その概算容量を超える見積もりに警告します。取得値は空きメモリやタブの使用可能量ではありません。iPhone・iPad（Macとして識別されるタッチ対応iPadを含む）では1.5GB超で「解像度を下げるか分割してください」と表示します。1.5GBはこのアプリの警告基準で、OSの固定上限ではありません。警告は処理を禁止しません。

表示のMB・GBは10進単位です。Device Memory APIのGiB値はバイトに換算して比較します。

切り出し時は、元ファイルのサイズに「指定時間 / 全体の長さ」を掛けたサイズ × 6 + 512MBを目安にします。長さを取得できるまでは全体サイズで概算します。可変ビットレートや再エンコード後のサイズ増加は正確に予測できません。結合時は部分読み込みへの変更後も、従来の保守的な見積もりを使用しています。

## 警告と自動分割

処理目安は、取得できた端末メモリの25%と、iPhone/iPadの1.5GB・その他のモバイル端末の1GB・PCまたは判別できない端末の2GBのうち、小さい値です。アプリ独自の保守的な方針であり、OSの制限や空き容量の実測ではありません。高解像度の変換はモバイル端末や少ない論理CPU数の端末でも警告します。

警告から「映像を分割する」「音声を分割する」で元ファイルを保持したまま切り出しに移動できます。警告中の処理は確認チェックが必要で、ファイル・範囲・推定量・設定の変更時は確認を解除します。コピー結合に失敗し、自動H.264変換で処理目安を超える場合も変換前に停止します。

分割秒数はファイルサイズと尺からの概算が処理目安の75%に収まるよう算出します（通常は1〜300秒、1秒未満のファイルはその長さ）。映像のフレーム作業領域と音声出力のビットレートも考慮します。両方の元ファイルがほぼ同じ尺の場合は短い方の推奨秒数にそろえます。短い区間でも作業領域が目安を超える端末では、警告を残して解像度低下や別端末の利用を案内します。結合の概算にも、既知の動画尺に合わせた音声ループ出力の増加分と、映像変換時のフレーム作業領域を加えます。

長さの取得後にデフォルト秒数を設定し、手動編集を後から上書きしません。ブラウザで長さが分からない場合は最初の実行で部分読み込みによる情報取得だけを行い、推奨範囲を確認してから再実行できます。「1 / N 本目」、残り本数、連番付きファイル名を表示し、保存確認後に次へ進むたびに元の秒数を維持し、最後だけ短縮します。
